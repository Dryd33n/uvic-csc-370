\section*{Overview}

This document formalizes the domain, primary key, and referential integrity (foreign key) constraints for the \texttt{stock\_trading} database using Relational Algebra expressions.

\section{Referential Integrity Constraints (Foreign Keys)}

Referential integrity constraints prevent orphaned records by ensuring that foreign key values in child relations correspond to existing primary keys in parent relations. In relational algebra, these are expressed as subset inclusions ($\pi_{FK}(R_1) \subseteq \pi_{PK}(R_2)$) or set difference empty-set equations ($\pi_{FK}(R_1) \setminus \pi_{PK}(R_2) = \emptyset$).

\subsection{\texttt{transaction.user\_id} \texorpdfstring{$\rightarrow$}{->} \texttt{user.user\_id}}

Every transaction must belong to a registered user.
\begin{itemize}[leftmargin=*]
  \item \textbf{Subset Inclusion:}
  \[
    \pi_{\text{user\_id}}(\text{Transaction}) \subseteq \pi_{\text{user\_id}}(\text{User})
  \]
  \item \textbf{Set Difference (Empty-Set):}
  \[
    \pi_{\text{user\_id}}(\text{Transaction}) \setminus \pi_{\text{user\_id}}(\text{User}) = \emptyset
  \]
\end{itemize}

\subsection{\texttt{transaction.ticker} \texorpdfstring{$\rightarrow$}{->} \texttt{stock.ticker}}

Every transaction must reference an existing stock ticker.
\begin{itemize}[leftmargin=*]
  \item \textbf{Subset Inclusion:}
  \[
    \pi_{\text{ticker}}(\text{Transaction}) \subseteq \pi_{\text{ticker}}(\text{Stock})
  \]
  \item \textbf{Set Difference (Empty-Set):}
  \[
    \pi_{\text{ticker}}(\text{Transaction}) \setminus \pi_{\text{ticker}}(\text{Stock}) = \emptyset
  \]
\end{itemize}

\subsection{\texttt{holds.user\_id} \texorpdfstring{$\rightarrow$}{->} \texttt{user.user\_id}}

Every stock holding record must reference a valid user.
\begin{itemize}[leftmargin=*]
  \item \textbf{Subset Inclusion:}
  \[
    \pi_{\text{user\_id}}(\text{Holds}) \subseteq \pi_{\text{user\_id}}(\text{User})
  \]
\end{itemize}

\subsection{\texttt{holds.ticker} \texorpdfstring{$\rightarrow$}{->} \texttt{stock.ticker}}

Every stock holding record must reference a valid stock ticker.
\begin{itemize}[leftmargin=*]
  \item \textbf{Subset Inclusion:}
  \[
    \pi_{\text{ticker}}(\text{Holds}) \subseteq \pi_{\text{ticker}}(\text{Stock})
  \]
\end{itemize}

\section{Key \& Uniqueness Constraints}

Key constraints ensure that primary keys uniquely identify tuples without duplicates. A set of attributes $K$ is a key of $R$ if no two distinct tuples of $R$ agree on $K$. Since a relation is a set, two tuples are distinct exactly when they differ in at least one attribute. Because they already agree on $K$, they must differ in some attribute outside $K$. So for a relation $R$ with key $K$ and non-key attributes $A_1, \dots, A_n$, the key constraint is:
\[
  \sigma_{r_1.K = r_2.K \;\land\; (r_1.A_1 \neq r_2.A_1 \,\lor\, \cdots \,\lor\, r_1.A_n \neq r_2.A_n)}\left(\rho_{r_1}(R) \times \rho_{r_2}(R)\right) = \emptyset
\]
Every non-key attribute must appear in the disjunction. If one is left out, two tuples with the same key that differ only in that attribute would not be selected, and the duplicate key would go undetected.

\subsection{Uniqueness of \texttt{user.user\_id}}

No two distinct users can share the same \texttt{user\_id}:
\[
  \sigma_{u_1.\text{user\_id} = u_2.\text{user\_id} \;\land\; (u_1.\text{name} \neq u_2.\text{name} \,\lor\, u_1.\text{email} \neq u_2.\text{email})}\left(\rho_{u_1}(\text{User}) \times \rho_{u_2}(\text{User})\right) = \emptyset
\]

\subsection{Uniqueness of \texttt{stock.ticker}}

No two distinct stocks can share the same \texttt{ticker}:
\[
  \sigma_{\substack{s_1.\text{ticker} = s_2.\text{ticker} \;\land\; (s_1.\text{company\_name} \neq s_2.\text{company\_name} \,\lor\, s_1.\text{opening\_price} \neq s_2.\text{opening\_price} \\ \lor\, s_1.\text{closing\_price} \neq s_2.\text{closing\_price} \,\lor\, s_1.\text{exchange} \neq s_2.\text{exchange})}}\left(\rho_{s_1}(\text{Stock}) \times \rho_{s_2}(\text{Stock})\right) = \emptyset
\]

\subsection{Uniqueness of \texttt{transaction.transaction\_id}}

No two distinct transactions can share the same \texttt{transaction\_id}:
\[
  \sigma_{\substack{t_1.\text{transaction\_id} = t_2.\text{transaction\_id} \;\land\; (t_1.\text{user\_id} \neq t_2.\text{user\_id} \,\lor\, t_1.\text{ticker} \neq t_2.\text{ticker} \\ \lor\, t_1.\text{transaction\_type} \neq t_2.\text{transaction\_type} \,\lor\, t_1.\text{quantity} \neq t_2.\text{quantity} \\ \lor\, t_1.\text{price} \neq t_2.\text{price} \,\lor\, t_1.\text{time} \neq t_2.\text{time})}}\left(\rho_{t_1}(\text{Transaction}) \times \rho_{t_2}(\text{Transaction})\right) = \emptyset
\]

\subsection{Composite Key Uniqueness of \texttt{holds(user\_id, ticker)}}

No user can have multiple holding entries for the exact same stock ticker:
\[
  \sigma_{h_1.\text{user\_id} = h_2.\text{user\_id} \;\land\; h_1.\text{ticker} = h_2.\text{ticker} \;\land\; (h_1.\text{quantity} \neq h_2.\text{quantity} \,\lor\, h_1.\text{average\_price} \neq h_2.\text{average\_price})}\left(\rho_{h_1}(\text{Holds}) \times \rho_{h_2}(\text{Holds})\right) = \emptyset
\]

\subsection{Candidate Key Uniqueness of \texttt{user.email}}

An email address can register only one account, so \texttt{email} is a second candidate key of \texttt{user} (enforced as \texttt{UNIQUE}). No two distinct users can share the same \texttt{email}:
\[
  \sigma_{u_1.\text{email} = u_2.\text{email} \;\land\; (u_1.\text{user\_id} \neq u_2.\text{user\_id} \,\lor\, u_1.\text{name} \neq u_2.\text{name})}\left(\rho_{u_1}(\text{User}) \times \rho_{u_2}(\text{User})\right) = \emptyset
\]

\section{Domain \& Value-Range Constraints (\texttt{CHECK} Constraints)}

Domain constraints restrict attribute values to valid business ranges using selection operations evaluated against the empty set ($\sigma_{\text{condition}}(R) = \emptyset$).

\subsection{Non-Positive Transaction Quantities}

Transaction quantities must strictly be positive ($> 0$):
\[
  \sigma_{\text{quantity} \le 0}(\text{Transaction}) = \emptyset
\]

\subsection{Non-Positive Execution Prices}

Transaction execution prices must strictly be positive ($> 0$):
\[
  \sigma_{\text{price} \le 0}(\text{Transaction}) = \emptyset
\]

\subsection{Restricted Transaction Types}

Transaction types must strictly be either \texttt{'buy'} or \texttt{'sell'}:
\[
  \sigma_{\text{transaction\_type} \notin \{\text{'buy'}, \text{'sell'}\}}(\text{Transaction}) = \emptyset
\]

\subsection{Negative Stock Holdings Quantity}

Portfolio holding quantities cannot be negative ($\ge 0$):
\[
  \sigma_{\text{quantity} < 0}(\text{Holds}) = \emptyset
\]

\subsection{Non-Positive Average Purchase Prices}

The average price paid for a holding must strictly be positive ($> 0$):
\[
  \sigma_{\text{average\_price} \le 0}(\text{Holds}) = \emptyset
\]

\subsection{Non-Positive Stock Prices}

Stock opening and closing prices must strictly be positive ($> 0$):
\[
  \sigma_{\text{opening\_price} \le 0}(\text{Stock}) = \emptyset
  \qquad
  \sigma_{\text{closing\_price} \le 0}(\text{Stock}) = \emptyset
\]
